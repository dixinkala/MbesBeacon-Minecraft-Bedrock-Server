# 06 备份与恢复

[← 返回目录](README.md)

「⑥ 世界备份」管理服务器 `worlds/` 的快照。

## 立即备份

- 把当前 `worlds/` 复制到备份目录，生成带时间戳的快照
- 备份目录默认在服务器目录同级的 `_worlds_backups/`
- 备份列表显示时间与体积，可按时间排序

## 自动备份

触发时机：

| 场景 | 说明 |
|---|---|
| 服务器更新前 | 先备份再下载安装 |
| 删除服务器前 | 先备份再删除（两种模式都会备份） |
| 世界导入前 | 先备份当前 `worlds/` |
| 恢复备份前 | 先把当前世界快照一份，便于反悔 |

## 保留策略

- 默认保留最近 **10** 个备份，超出自动清理最旧的
- 上限可配置，最大 **100**
- 清理只匹配 `{服务器名}_worlds_{YYYYmmdd_HHMMSS}` 命名的目录，**不会误删用户自己的文件夹**

## 恢复

1. 在列表中选择备份，点「恢复」
2. 若服务器运行中，先自动停止
3. 当前 `worlds/` 先重命名暂存（不是直接删除）
4. 备份内容复制到位
5. 任一步失败会**回滚**：删掉半成品，恢复原来的 `worlds/`

## 删除备份

- 选中备份删除，二次确认
- 只删备份目录，不影响在线世界

## ZIP 导出

- 可把某次备份打成 ZIP 下载，便于归档或迁移
- 文件名含服务器名与时间戳

## 备份内容与边界

| 包含 | 不包含 |
|---|---|
| `worlds/` 下所有世界目录 | `server.properties`、白名单、权限文件（这些属于配置，见 [02](02-config.md)） |
| 世界内的 `level.dat`、`db/` 等 | 资源包/行为包（见 [07](07-packs.md)） |

> 完整迁移请整体复制 `%APPDATA%\MbesBeacon` 与服务器目录，见 [11](11-security-data.md)。

## 恢复失败怎么办

恢复过程有回滚保护；若仍失败，检查：

1. 磁盘剩余空间是否充足（世界可能很大）
2. 服务器是否确实已停止（进程占用会导致文件操作失败）
3. 备份目录是否被手动移动/改名

错误详情会写入审计日志与应用日志。
